# AudioShare USB Companion v1.0.0-rc.4

Fourth public release candidate for the Android USB playback companion.

## Reliability fixes

- Preserves nested Android playback causes across the USB protocol, allowing
  the Windows supervisor to distinguish phone media taking audio focus from a
  transient cable or transport failure.
- Prevents a reconnect loop when music or video is started directly on the
  phone. The matching Windows host now stops once and gives a clear recovery
  instruction.
- Fixes a reproduced startup race in which the playback thread could access its
  speaker-route grace tracker before Kotlin initialized that field.

## Validation fixes

- Updates the real-device protocol smoke tool for the current 92-byte playback
  diagnostics payload while retaining validation of the older 24/60-byte forms.
- Validates frames written, playback-head progress, progress ages, play state,
  and actual AudioTrack performance mode during physical-device testing.

## Physical-device evidence

- The patched debug companion passed a 15-second Samsung Galaxy A52s session:
  720,000 frames received/written, zero dropped frames, zero underruns, confirmed
  built-in-speaker route and audio focus, active session wake lock, clean service
  shutdown, and exact ADB-forward removal.
- A controlled Samsung Music focus takeover produced the expected terminal text
  `AudioTrack playback failed: Android audio focus was lost`; phone media was
  returned to its prior paused state after the test.

RC4 remains a prerelease until the signed APK is paired with and revalidated in
the matching Windows portable release and the longer manual endurance gates are
completed.
